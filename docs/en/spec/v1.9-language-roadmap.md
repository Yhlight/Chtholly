# Chtholly 1.9 Language Roadmap

Chtholly 1.9 deepens the frozen iterator model with mutable callable
algorithms, projection-sensitive borrow continuations, and ordinary library
protocols for shared collection views and verified collection construction.
It adds no source grammar, lifetime annotation, or runtime representation.

## Mutable Callable Iteration

The `std::iter::mutable` module provides `PredicateMut<Args>`,
`FolderMut<Accumulator, Item>`, `MapMut<I, F>`, `FilterMut<I, P>`, and the
functions `map_mut`, `filter_mut`, `fold_mut`, `any_mut`, and `all_mut`.
Mutable algorithms own their callable state and invoke it through `Self&`.
`filter_mut` copies an Item for predicate testing and therefore retains the
existing copy requirement.

A mutable callable may retain an external receiver borrow and return an Item
derived from that receiver. The Item and continuation remain separate return
carriers. Moving the continuation is allowed, but invoking it while the prior
Item remains live is rejected as an overlapping mutable borrow. Authority is
available again after the Item's final use or lexical exit. A reference into
owned storage that moves inside its own continuation remains invalid; 1.9 does
not introduce pinning or self-referential object semantics.

The rule is structural. It uses callable return provenance and carrier paths,
not standard-library function names. Switch arms, scoped value blocks, yields,
and loop backedges preserve the same provenance and cleanup facts.

## Collection And Collector Protocols

The `std::collections` module defines the minimal shared source and construction
protocols:

```cns
pub trait Collection {
  alias Iterator;
  fn items(self: const Self&): Self::Iterator contract {
    borrows shared self;
    returns borrow self;
  }
}

pub trait Collector<Item> {
  alias Output;
  fn push(self: Self&, item: Item): void;
  fn finish(self: Self): Output;
}

pub fn collect<I, C>(iterator: I, collector: C): C::Output
    where I: std::iter::Iterator,
          C: Collector<I::Item>;
```

`Collection` associates only its iterator. The element type is
`Collection::Iterator::Item`, so 1.9 needs no associated-type equality syntax.
The method is named `items` to remain distinct from container-specific inherent
iterator constructors.

`VecView<T>` plus `view(const Vec<T>&)` is the standard shared Collection
adapter; keeping the conformance in the 1.9 module avoids adding a reverse
dependency to the frozen `std::vec` module. `VecCollector<T>` is the standard
collector state. `vec_collector` accepts an initialized `Vec<T>`, `push`
appends owned Items, and `finish` returns the Vec. This keeps target type
deduction in ordinary call arguments. The frozen 1.7 `collect_vec` algorithm
remains available with unchanged behavior.

Mutable collection views, consuming collection protocols, fallible collectors,
size hints, and persistent collections of borrowed Items are outside 1.9.

## Compiler And Artifact Contract

Dependent constraint lists are resolved in source order through an explicit
obligation worklist. An associated projection in a later constraint observes
only inherited and already completed constraints; it cannot recursively parse
its own list.

Callable ownership builds real Switch CFG edges and propagates provenance
through Yield, ScopedBlock, If, and Switch results. Region paths longer than
256 steps widen to the parameter root. Postcondition loops that exhaust the
same bounded fixed-point budget widen affected parameter roots to all possible
outcomes rather than claiming an exact transition.

PlaceState retains the existing return carrier paths on derived loans. Enum and
field projection consume those paths, keeping sibling Item and continuation
loans distinct. A mutable returned loan is checked as borrow formation at the
call site. Repeated projection cycles conservatively widen to an absorbing root
loan and are reported through analysis metrics; this changes proof precision,
not source or ABI behavior.

The carrier-path wire shape is unchanged. Architecture V6 additionally closes
aggregate value representation over in-place elements and persists exact
callable signatures for concrete call targets. The semantic artifact epoch is
17, standard-library epoch is 9, compiler contract is 14, API epoch is 16, and
cache namespace is `next-v38`. Concrete specialization components use format
46; artifacts with older semantic or component versions fail closed.
