# Chtholly 1.5 Language Roadmap

Chtholly 1.5 generalizes the frozen 1.4 `foreach` statement through a static
standard-library iterator protocol. The grammar, binding spelling, explicit
transfer requirement, structured cleanup, and continuation-based lowering are
unchanged.

## Iterator Protocol Generalization

The canonical protocol is declared by `std::iter`:

```cns
pub enum IterationStep<Item, Continuation> {
  Item { Item, Continuation },
  Done,
}

pub trait Iterator {
  alias Item;
  fn next(self: Self): IterationStep<Self::Item, Self>;
}
```

The expression after `in` must produce an owned value with exactly one verified
`std::iter::Iterator` witness. A named iterator place still requires an
ordinary explicit transfer. The compiler resolves the associated `Item` alias
and concrete `next` target through the witness; method spelling or nominal type
names do not establish conformance.

`next` consumes `Self`. `Item` carries the element and the exact continuation
`Self`; `Done` has no payload. The continuation is moved back into the hidden
loop local before the user body starts.

If `Item` is a reference, foreach copies that reference and preserves its
verified borrow-carrier provenance. If `Item` is an owned value, foreach moves
the payload into the binding. Foreach never implicitly copies an owned item and
does not apply an item conversion. An explicit annotation must be canonically
identical to the associated `Item` type.

Shared and mutable Vec iterators implement the protocol. Their historical
`VecIterStep<T>` and `VecMutIterStep<T>` names remain transparent aliases to
the standard step type. Chtholly 1.4 continues to admit only these canonical
Vec intrinsic witnesses; general user conformances require language 1.5.

User-defined owned-item and shared-reference iterators are admitted locally,
through generics, and across package artifacts. A general user-defined mutable
reference iterator is not admitted in this release: returning an exclusive
Item reference together with a continuation that retains the same exclusive
owner requires a future staged-loan or reborrow capability. Canonical
`VecMutIterator` remains supported by its compiler-verified contract. The
compiler does not weaken ordinary exclusive-borrow rules to emulate that
capability.

## ABI And Artifacts

Iteration uses ordinary interface declarations, associated aliases, witnesses,
callable ownership summaries, borrow-carrier paths, enum values, calls, switch,
and structured loop instructions. It adds no runtime symbol, calling convention,
SemIR opcode, source lifetime annotation, or artifact wire field.

The standard-library compiler contract is 9, API epoch is 13, and standard-
library compatibility epoch is 6. Existing public interface and specialization
formats remain valid; changed standard entities receive new canonical
fingerprints and old standard-library dependencies fail closed at the language
contract boundary.
