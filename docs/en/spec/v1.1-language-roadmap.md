# Chtholly 1.1 Language Roadmap

Status: frozen scope layered on the frozen Chtholly 1.0 language. Packages
select it explicitly with `package.language = "1.1"`; direct compilation keeps
the stable 1.0 default.

The release adds no compatibility aliases and does not revise the frozen 1.0
production. Both planned closure waves are normative and complete; later work
requires a new versioned roadmap.

## Concurrency Memory Core

The first wave freezes the data-race boundary already anticipated by the
abstract machine and admits a narrow standard-library surface for scalar
atomics and volatile foreign-memory access. Atomic ordering follows the
target-independent LLVM and C++20 model. Transfer and sharing are compiler
derived semantic facts, not user assertions.

The admitted source API and verifier obligations are defined in
`concurrency-and-atomic-memory.md`. Pointer atomics, fences, floating and
aggregate atomics, atomic wait/notify, weak compare-exchange, volatile
bitfields, and a general volatile-qualified type are outside 1.1.

## Async And Program Model Wave

The second wave freezes public `async fn`, prefix `wait`, `check cancel;`, and
lexical `task scope`, together with the single hosted
`async fn main(): i32` entry. Task transfer and scheduling consume the first
wave's compiler-derived transfer/share facts and memory model. They do not
introduce a coroutine-specific data-race exception.

The hosted runner is compiler-generated over task runtime v1. Standard-library
manifest format 4 and `CHNXTPK63` artifacts persist the module and foreign
symbol closure, so executable linking follows only modules reachable from the
selected root. The complete source, process, runtime, and link contract is in
`async-and-hosted-program-model.md`.

Detach, manual cancellation, executor syntax, timeout syntax, async entry
parameters, freestanding startup, and recoverable cancellation remain outside
1.1.

## Explicitly Deferred

Environment-bearing callable values, bound method values, operator protocols,
dynamic interface values, freestanding startup, labeled control flow, and
module aliases remain outside 1.1. They receive later versioned roadmaps rather
than extending this candidate after implementation begins.
