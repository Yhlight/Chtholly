# Chtholly 1.2 Language Roadmap

Chtholly 1.2 extends the frozen 1.1 surface without changing its source or ABI
contracts. The callable waves are complete and the 1.2 surface is frozen;
operator overloading remains the next design boundary for a later release.

## Environment-Bearing Callables

The first wave adds statically typed closure objects with explicit owned
captures. Each expression has a unique anonymous type and a field-only
environment. Calls use a compiler-generated body with a hidden checked
environment reference; they do not allocate, erase the environment, or change
the v1 `fn(T...): U` pointer representation.

Capture, invocation, lifecycle, concurrency, public-template, and module rules
are specified in [environment-bearing-callables.md](environment-bearing-callables.md).
The implementation review is closed with an explicit SemIR/artifact closure
descriptor, capability derivation from body effects, and stable cross-module
hidden-target identity; the physical field-only environment ABI is unchanged.

## Callable Interfaces

`std::callable::Invoke<Args>`, `InvokeMut<Args>`, and `InvokeOnce<Args>` are ordinary public traits
with an associated `Output`; `Args` is a single tuple type. The compiler
synthesizes witnesses for owned closures according to their capture facts,
using a tuple adapter to reach the existing direct-call body. Witnesses use
canonical interface/type/function fingerprints and are rematerialized through
the existing imported-interface resolver. Erased callables and foreign/unsafe
values remain excluded.

## Bound Method Values

Bound method values are the second 1.2 wave. They reuse the reviewed closure
environment ABI by representing the receiver as a checked read-only, mutable,
or owned capture. Consuming receivers use `InvokeOnce`; no separate delegate
representation is reserved. Formation, capability, lifetime, and artifact
rules are specified in [bound-method-values.md](bound-method-values.md).
Focused validation covers all three receiver capabilities, adapter parameter
ordering, retained receiver loans, consuming calls, public generic
provider/consumer materialization, repeated-session identity, and malformed
artifact rejection.

## Operator Overloading

General operator overloading remains pending until the explicit closure,
callable-interface, and bound-method call ABIs have passed implementation
review. No operator is redirected to user code in the closure core.

## Explicitly Deferred

Type-erased callable storage, heterogeneous callable containers, reference
captures, inferred/default captures, async closure syntax, and closure types in
public declaration signatures remain outside the 1.2 candidate. Generic
callable constraints and compiler-generated adapters
remain static and do not imply type erasure or a heterogeneous storage ABI.
