# Chtholly 1.3 Language Roadmap

Chtholly 1.3 extends the frozen 1.2 surface with explicit operator protocols.
Operator expressions use ordinary standard-library traits and the existing
witness/call ABI; no operator-specific runtime representation is introduced.
It also admits module aliases and labeled structured-loop control. These forms
are gated as 1.3 source syntax and are not part of the 1.0-1.2 surfaces.

CFDL is independent from the 1.3 language surface. The current Next CFDL is a
separate binding language for ordinary foreign declarations and finite
resource-flow `where` facts; it publishes an immutable Interop artifact that
Chtholly consumes through ordinary imports. The normative source and artifact
boundary is defined by [`cfdl.md`](cfdl.md). This roadmap does not add CFDL
syntax, operation objects, capability paths, `bind`, or FFI-specific source
contracts. Further CFDL work is tracked by the Next CFDL resource-flow design
and its implementation evidence.

## Operator Core

The implemented catalog admits unary negation and bitwise complement,
arithmetic, bitwise, shift, equality, and comparison operations for nominal
types and constrained type parameters. The protocol module is `std::ops` and
must be imported explicitly. Builtin scalar operations retain their existing
checked, constant-evaluable semantics and do not become user-overridable.

Non-assignment operators borrow each operand as a `const` checked reference.
`Output` is an associated type for arithmetic, negation, bitwise, and shift
protocols. `!=` is the logical negation of `Equality::equal`; ordering
operators inspect the `std::compare::Ordering` returned by
`Comparison::compare`.

The fixed protocol mapping is:

| Expression | Interface requirement | Result |
| --- | --- | --- |
| `-value` | `Negation::negate` | `Self::Output` |
| `left + right` | `Addition::add` | `Self::Output` |
| `left - right` | `Subtraction::subtract` | `Self::Output` |
| `left * right` | `Multiplication::multiply` | `Self::Output` |
| `left / right` | `Division::divide` | `Self::Output` |
| `left % right` | `Remainder::remainder` | `Self::Output` |
| `~value` | `BitwiseComplement::complement` | `Self::Output` |
| `left & right` | `BitwiseAnd::bit_and` | `Self::Output` |
| `left ^ right` | `BitwiseXor::bit_xor` | `Self::Output` |
| `left \| right` | `BitwiseOr::bit_or` | `Self::Output` |
| `left << right` | `LeftShift::shift_left` | `Self::Output` |
| `left >> right` | `RightShift::shift_right` | `Self::Output` |
| `left == right` | `Equality::equal` | `bool` |
| `left != right` | `Equality::equal` plus logical negation | `bool` |
| `left <=> right` | `Comparison::compare` | `std::compare::Ordering` |
| `<`, `<=`, `>`, `>=` | `Comparison::compare` plus ordering inspection | `bool` |

There is no operator declaration syntax. Implementations use ordinary
`impl std::ops::Interface<...> for Type` declarations, which keeps coherence,
visibility, generic constraints, and diagnostics on the existing interface
path.

User-defined shift protocols do not inherit builtin integer width, overflow,
or signedness rules. Those rules remain properties of builtin scalar
operations; a protocol implementation defines its own result semantics.

## Compound Assignment

Compound assignment for nominal types and constrained type parameters uses a
separate mutable protocol catalog. Every requirement receives `self: Self&`,
borrows the right operand as `const Rhs&`, and returns `void`:

| Statement | Interface requirement |
| --- | --- |
| `left += right` | `AdditionAssignment<Rhs>::add_assign` |
| `left -= right` | `SubtractionAssignment<Rhs>::subtract_assign` |
| `left *= right` | `MultiplicationAssignment<Rhs>::multiply_assign` |
| `left /= right` | `DivisionAssignment<Rhs>::divide_assign` |
| `left %= right` | `RemainderAssignment<Rhs>::remainder_assign` |
| `left &= right` | `BitwiseAndAssignment<Rhs>::bit_and_assign` |
| `left ^= right` | `BitwiseXorAssignment<Rhs>::bit_xor_assign` |
| `left \|= right` | `BitwiseOrAssignment<Rhs>::bit_or_assign` |
| `left <<= right` | `LeftShiftAssignment<Rhs>::shift_left_assign` |
| `left >>= right` | `RightShiftAssignment<Rhs>::shift_right_assign` |

The destination place is evaluated once, then the right operand is evaluated
once. Its read-only argument is established before the mutable receiver borrow;
the ordinary method call is the mutation boundary. Failures before invocation
perform no compound-assignment mutation, although right-operand side effects
are not rolled back. Once the method begins, unrecoverable termination does not
roll back mutations already performed by the implementation.

Builtin scalar compound assignment retains the stronger compiler-managed
candidate-and-commit path: it reads the old value, checks the destination-typed
operation, and emits one assignment only after success. Both forms are
statements with no result and cannot be chained or used as values.

## Outside 1.3

Operator-derived indexing or conversion, operator reverse dispatch, implicit
conversions during operator lookup, and operator declaration syntax remain
outside the 1.3 surface. The compiler-level foreign callback reverse-target
closure is tracked separately and does not add operator syntax. Short-circuit
logic, logical negation, calls, and indexing retain their existing
compiler-owned semantics.

## Module Aliases

An import may bind a local module alias:

```cns
import provider as p;
export import provider as public_provider;
```

The alias is the only local qualifier introduced by that declaration. Alias
lookup participates in duplicate-import and local-name collision checks. An
exported alias forwards the provider's public entities while preserving their
canonical package, module, name, and fingerprint identities. Consumers do not
acquire authority to publish provider-private entities.

Module aliases require language version 1.3 or newer. Earlier source versions
emit `chtholly.next.version.module-alias-requires-1-3` at the alias clause.

## Labeled Loop Control

A label is an identifier and colon immediately preceding `while`, `for`,
`do...while`, or, beginning with 1.4, `foreach`:

```cns
outer: while (condition) {
  if (done) { break outer; }
  continue outer;
}
```

`break label` exits the named active loop. `continue label` transfers to that
loop's ordinary continuation point. Both operations run the same lexical
defer, lifetime-end, and destruction cleanup as an equivalent sequence of
unlabeled exits. Labels are scoped to active enclosing loops, cannot be
duplicated in that stack, and cannot introduce a non-loop statement.

Loop labels require language version 1.3 or newer. Earlier source versions emit
`chtholly.next.version.loop-label-requires-1-3`.

## Reverse Dispatch Infrastructure

The compiler-level reverse-dispatch route now covers local and imported
ordinary functions plus concrete canonical interface-witness entries. One
SemIR query owns target admissibility so semantic conversion, SemIR
verification, and LowIR construction cannot drift. LowIR's unified reverse
thunk model records target kind, direct/context-entry/context-release role,
typed context carrier, and sorted canonical witness fingerprints.

Imported instance functions remain closed unless a complete non-generic
witness names the exact canonical entity. This reuses the provider native
definition export closure and consumer-local thunk infrastructure without
adding erased interface dispatch, hidden allocation, operator syntax, or a new
serialized witness ABI.

The foreign binding route is outside the Chtholly source surface. CFDL uses
ordinary foreign declarations plus finite resource-flow `where` facts and
publishes an immutable Interop artifact. Chtholly consumes the resulting
entities through ordinary imports; `extern`, `bind`, operation objects, and
FFI-specific source contracts are not supported.

## ABI And Compatibility

An overloaded operator is represented as an ordinary direct call or symbolic
interface call. Public generic artifacts therefore reuse existing interface
fingerprints, witness entries, and concrete specialization rules. The expanded
catalog advances the standard-library API epoch to 6 and standard-library
compatibility epoch to 4. The semantic artifact epoch and compiler-contract
epoch remain unchanged because no artifact encoding or compiler intrinsic
contract changes.

`T::Output` in a public generic signature is encoded as an associated
projection containing the constrained subject, the canonical interface entity,
and the associated-alias binding slot. Local public interfaces are finalized
before function entity fingerprints are computed, so exported templates never
retain a provisional semantic fingerprint. Artifact verifiers reject malformed
projection kinds, interface identities, and out-of-range encoded slots before
materialization.

Cross-module native witness execution uses a compilation-local native definition
export closure. Published witness entries seed exact provider implementation
roots, including source-private concrete implementations; generic templates,
imported targets, and unrelated helpers remain outside the provider object
closure. This changes no operator syntax, witness artifact encoding, or runtime
ABI.

## Post-Freeze Standard-Library Direction

The first post-v1.3 library wave is `std::vec::Vec<T>`. It is a contiguous
affine owner with borrowed `VecIterator<T>` and `VecMutIterator<T>` values.
Element moves transfer only the selected element. Structural operations such as
`reserve`, `push`, and `clear` are ordinary mutable owner writes; they may
relocate storage and therefore cannot overlap a live element loan or iterator.
This direction reuses the existing callable-effect and provenance ABI and does
not add lifetime parameters, generation fields, or `foreach` syntax.
