# Chtholly 1.10 Language Roadmap

Chtholly 1.10 closes the integer-width inconsistency between the physical slice
representation and its source operations. It also adds the standard
`ReadOutcome<T>` vocabulary required by checked CFFI read projections. CFDL
remains a separate binding language and is specified in `cfdl.md`.

## Wide Slice Semantics

In language 1.10, `slice<T>.len`, array and slice dynamic indices, and both
bounds of a slice expression use `u64`. The physical slice remains a pointer
plus an unsigned 64-bit element count. Indexing traps before an inbounds address
is formed when the index is outside the array or slice. Slicing traps unless
`start <= end <= len`.

Language versions 1.0 through 1.9 retain their frozen `i32` source behavior.
There is no implicit compatibility conversion between the two contracts; a
package selects the behavior with its language version.

An already-checked generic body keeps the index types selected by its provider
version when instantiated by a package using another supported version. This
is typed artifact preservation, not an additional source conversion.

## Read Outcome

`std::io` exports:

```cns
pub enum ReadOutcome<T> {
  Data { T },
  Eof,
}
```

The type is ordinary Chtholly source vocabulary. A verified CFDL
`posix_read<T>` outcome may project a native call to
`Result<ReadOutcome<slice<T>>, i32>`. `Data` carries the initialized prefix of
the caller-provided buffer. `Eof` is distinct from an empty request: a
zero-capacity call returning zero produces `Data` with an empty slice.

A verified synchronous `win32_read<T>` outcome exposes the same public data
classification with a `u32` Win32 error. Its physical count and null context
lanes are compiler-owned and are not additional Chtholly call arguments.

Linux `recv` bindings reuse the POSIX projection with ordinary socket and flags
lanes preserved in the call signature. No new source syntax is required.

The V22 follow-up adds a specialized Linux `fread<T>` outcome. It models the
returned element count together with explicit `feof` and `ferror` accessors;
error precedence, EOF classification, short-read traps, and byte-prefix
lengths are checked by the compiler without introducing generic
`buffer_prefix` syntax.

## Compiler And Artifact Contract

The semantic artifact epoch is 26 and the standard-library epoch is 12.
Package state is `CHNXTPK78` format 76, the compiler cache uses the `next-v47`
family with a contract- and target-qualified namespace, and concrete
specializations use `CHNXSCC50` component version 50. Typed-channel
specializations persist the canonical MultiSubmit outcome fingerprint; older persisted
formats fail closed.
The native C ABI, Component ABI epoch 1, and runtime ABI v1 are unchanged.
