# Chtholly 1.8 Language Roadmap

Chtholly 1.8 adds fieldless value enums without changing the existing algebraic
data type enum model. A declaration is a value enum when any variant has an
explicit `=` discriminant.

## Declaration And Values

Every value-enum variant must declare a unique signed 32-bit integer literal:

```cns
enum Color {
  Red = 10,
  Green = 20,
  Blue = -4,
}

let color = Color::Red;
```

Positive and negative literals are admitted, including the complete i32 range.
Implicit numbering, duplicate values, out-of-range values, and non-literal
constant expressions are rejected. Value enums cannot have payload fields,
generic parameters, where constraints, lifecycle attributes, or representation
controls. Existing ADT enums retain ordinal tags and their existing payload,
generic, construction, ownership, and cleanup behavior.

A value variant is constructed only as `Color::Red`. Braced `Color::Red {}` is
rejected so the source surface distinguishes scalar enum values from ADT
construction. A value enum has a fixed size and alignment of 4 bytes.

## Conversion And Control Flow

The only numeric conversion is an explicit value-enum-to-`i32` cast:

```cns
let raw = color as i32;
```

There is no implicit enum-to-integer conversion and no integer-to-enum
conversion. Chtholly 1.8 does not synthesize arithmetic, equality, ordering, or
bitwise operators for value enums.

Switch patterns continue to identify variants by qualified name. Exhaustive
coverage, duplicates, and wildcard reachability are checked by declaration
identity and ordinal position; generated control flow compares the stored
declared discriminant. Consequently sparse and negative values do not weaken
closed-enum exhaustiveness.

## Compiler And Artifact Contract

SemIR and public nominal artifacts record both the value-enum fact and each
variant's discriminant. Generic, package, nominal-definition, and nominal-
specific artifacts fail closed when this metadata is stale. LowIR retains
ordinal payload projections for ADTs while LLVM stores the declared i32 value
for value enums.

The semantic artifact epoch is 14, standard-library epoch is 8, compiler
contract is 11, API epoch is 15, package state is CHNXTPK69/version 66, and
concrete specialization format is 45. Chtholly 1.8 adds no standard-library or
runtime ABI surface.
