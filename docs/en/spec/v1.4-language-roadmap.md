# Chtholly 1.4 Language Roadmap

Chtholly 1.4 extends the frozen 1.3 surface with one ownership-aware iterator
loop. The feature reuses the existing consuming Vec iterator protocol,
structured loop control, PlaceState ownership analysis, cleanup construction,
and compiler-intrinsic lowering. It adds no iterator trait, lifetime syntax,
implicit element conversion, or artifact ABI lane.

## Foreach Statement

The complete 1.4 grammar is:

```text
ForeachStatement :=
    [Identifier ":"]
    "foreach" "(" ForeachBinding "in" Expression ")" Block

ForeachBinding :=
    ("let" | "var") Identifier [":" Type]
```

Examples:

```cns
foreach (let item: const T& in values.iter()) {
  inspect(item);
}

foreach (var item: T& in values.iter_mut()) {
  update(item);
}

let iterator = values.iter();
foreach (let item in move iterator) {
  inspect(item);
}
```

`let` and `var` control whether the local binding can be rebound. Element
mutability is determined by the yielded reference type: `const T&` is shared
and `T&` is mutable. Omitting the type annotation infers that exact reference
type from the iterator protocol.

The expression after `in` is an ordinary Chtholly expression evaluated exactly
once. A named iterator place must be transferred explicitly, normally with
`move`. `copy` is permitted only when the iterator's ordinary lifecycle policy
permits copying. A borrowed expression is accepted only if its resulting type
itself satisfies the iterator protocol. Foreach adds no ownership operators or
special initialization grammar of its own.

The 1.4 protocol is deliberately closed to the canonical
`std::vec::VecIterator<T>` and `std::vec::VecMutIterator<T>` families. Their
consuming `next` function returns an enum with exactly these logical cases:

```text
Item { element_reference, continuation_iterator }
Done
```

Shared iteration yields `const T&`; mutable iteration yields `T&`. Foreach
never implicitly copies or moves `T`.

## Ownership And Lowering

The normative behavior is the existing-language expansion below:

1. Evaluate the iterator expression once and bind its owned result to a hidden
   loop-carried local.
2. Move that local into the concrete, specialized `next` function.
3. Bind the returned step to a hidden local and exhaustively switch on `Item`
   and `Done`.
4. In `Item`, copy the element reference, move the continuation, and assign the
   continuation to the loop-carried local before entering the user body.
5. In `Done`, break the loop.

Assigning the continuation before the body makes ordinary and labeled
`continue` transfer to the next valid iterator state. The Item reference and
step temporary remain scoped to the current iteration. A structural owner
write conflicts with the live iterator or Item loan. Neither the iterator nor
an Item reference may escape its owner or permitted loop scope.

## Cleanup And Control Flow

Foreach uses the same cleanup plans as other structured loops:

- normal fallthrough ends Item temporaries before the next `next` call;
- `continue` runs current-body cleanup and advances with the saved
  continuation;
- `break` destroys current Item, step, continuation, and loop locals before
  continuing after the loop;
- `return` runs the ordinary function return cleanup;
- labeled exits run cleanup for every exited lexical and loop scope.

References are non-owning and do not destroy the element. The owner destroys
each still-initialized non-trivial element exactly once on every exit path.

## Diagnostics

The dedicated diagnostics are:

| Condition | Diagnostic code |
| --- | --- |
| source version is earlier than 1.4 | `chtholly.next.version.foreach-requires-1-4` |
| malformed binding | `chtholly.next.parse.foreach.invalid-binding` |
| expression is not an admitted iterator | `chtholly.next.sem.foreach.invalid-iterator` |
| named iterator place lacks an explicit transfer | `chtholly.next.sem.foreach.move-required` |
| annotation differs from the yielded reference | `chtholly.next.sem.foreach.item-type-mismatch` |
| canonical iterator has a malformed Item/Done contract | `chtholly.next.sem.foreach.protocol-mismatch` |

Ordinary ownership violations continue to use the shared place, lifecycle,
borrow-conflict, and escape diagnostics. Valid or invalid foreach source must
not fall back to `UnsupportedSemantics`.
