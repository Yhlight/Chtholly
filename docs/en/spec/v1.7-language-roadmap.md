# Chtholly 1.7 Language Roadmap

Chtholly 1.7 unifies value-producing lexical blocks and adds the second
standard iteration library wave. It does not change the 1.4 foreach grammar or
the 1.5 Iterator protocol.

## Value Blocks And Callable Results

`{ statements; tail_expression }` is an expression. The final expression has
no semicolon and supplies the block value; an empty value block has type void.
The block is a real lexical cleanup region. Owned results leave the region
before reverse-order defer and local cleanup; references to block-local storage
cannot escape.

`unsafe { ... }` applies unsafe authority while checking the complete value
block and returns its value. Empty unsafe blocks therefore produce void.
Immutable `let` bindings may hold void without storage; void values cannot be
mutated, moved, borrowed, or stored in aggregates.

Function and closure bodies use the same value-block rule. A reachable tail
expression is adjusted to the declared result type and becomes the return
operand. A reachable void body with no tail value receives an implicit void
return. Non-void bodies without a value remain invalid, and never-returning
functions must diverge. Explicit return remains valid.

An independent `{ statements }` statement introduces a lexical scope and needs
no semicolon. Source versions before 1.7 retain their previous block and return
rules.

## Switch Statements

A switch statement has no trailing semicolon:

```cns
switch (value) {
  Type::First => { handle_first(); }
  Type::Second => return;
}
```

Each arm contains either one statement or a statement block and owns an
independent lexical scope. Closed enums still require exhaustive coverage or a
wildcard. Existing switch expressions continue to accept direct expressions or
value blocks, require compatible values from every reachable arm, and permit
diverging arms.

## Iterator Algorithms

The new `std::iter::algorithms` module provides:

```cns
Folder<Accumulator, Item>
enumerate<I>(I): Enumerate<I>
fold<I, A, F>(I, A, F): A
any<I, P>(I, P): bool
all<I, P>(I, P): bool
collect_vec<I>(I): std::vec::Vec<I::Item>
```

Enumerate is lazy and starts at zero. Fold consumes each accumulator and Item
and requires a read-only Folder returning the same accumulator type. Any and
all consume Items and short-circuit. Collect_vec accepts only movable owned
Items with object representation and no loan carrier; borrowed Items receive a
dedicated diagnostic.

The module is separate from the frozen 1.6 adapters surface. Mutable callable
algorithms, borrowed Vec storage, collection protocols, and borrow-carrying
callable continuations remain deferred.

## Compiler And Artifact Contract

Scoped blocks use an append-only SemIR instruction and generic-template opcode;
LowIR expands them into ordinary blocks and cleanup edges. Associated type
arguments remain symbolic through public generic intrinsic calls and are
canonicalized only after witness-dependent concrete specialization.

The semantic artifact epoch is 13, standard-library epoch is 8, compiler
contract is 11, API epoch is 15, package state is CHNXTPK68/version 65, and
concrete specialization format is 44.
